# 发热事件恢复运行手册草案（2026-08-14）

> 作者：grokA。只写阶段、准入与停止判据。  
> **不写**未经 Codex 主模型批准的具体万用表测点、试错接法或“再插一次试试”。  
> 历史上出现过 `ONLINE` / 短时双向 ACK，**不自动构成**下一轮重接或长期互连授权。

## 当前状态栏（2026-08-14 傍晚口径）

| 项 | 状态 |
|---|---|
| 正确接口 | Titan **独立 H1 三针**，不是 40 针 U18 |
| H1 三线交叉 + 独立 USB 供电 + 不接 VCC | 已做过；**15 秒**窗口无发热 |
| UART2 实物短时闭环 | **已验证**（`acked` 跟随 `sent`，`timeout=0`，`malformed=0`，`rx_errors=0`） |
| 长期互连热安全 / 10 分钟 / 断联恢复 | **未验收** |
| 两板 VCC 互连 | **禁止** |
| 舵机 6 V / 总线 / 姿态 / 校准 | **断开且未授权** |

发热事件本身仍有效：曾在错误接口（把 40 针电源脚当 GND）后明显发热。后续正确 H1 接法的短时成功**不能删除**那段历史。

**阶段 1～5 的新硬件动作仍须 Codex 逐阶段授权。** 本手册不是上电许可。

| 栏 | 内容 |
|---|---|
| 状态 | 任何新接线或再次长时间通电前应完成；可与已完成的短时闭环记录并存 |
| 前置条件 | 两板 USB 已拔；H1 与 40 针上无临时电源线；舵机 6 V 关闭且物理断开 |
| 操作人 | 用户；记录交给 Codex |

| 回滚 | 保持断电；不要清洁剂冲洗或带电吹风 |

## 阶段 4：Titan UART2 与隔离 USB-TTL 分方向验证

| 栏 | 内容 |
|---|---|
| 状态 | **未获执行授权** |
| 前置条件 | 阶段 2 中 Titan 单独供电无异常；Maix **不连接**；USB-TTL 为 3.3 V 逻辑；**只接 TX/RX/GND** |
| 操作人 | 用户；PC 端仅在三重门控后使用 `host/uart_segment_probe.py` |
| 允许动作 | 分方向：Titan TX→TTL RX、TTL TX→Titan RX；默认先 dry-run |
| 停止条件 | 接了 TTL 的 VCC、接到 40 针电源脚、发热、无 consoles |
| 所需证据 | Titan `sh_status` / 控制台；PC JSON；明确写 H1 而不是 U18 |
| 回滚 | 拔 TTL 与 Titan USB |

三重门控：`--port`、`--confirm-hardware`、波特率 `115200`。禁止枚举串口碰运气。

## 固定红线

- 禁止两板 `3V3`/`5V`/`VBUS` 互连。
- 禁止把 40 针 U18 当作 H1。
- 禁止猜针脚、换脚试错、带电测电压（除非 Codex 另授）。
- 禁止把 TX/RX 接反直接说成发热根因。
- 禁止接入舵机电源或解除 `actionable=0` / 空姿态拒绝。
- 禁止修改 `D:\Micu\RTTWorkspace\titan_uart_test`、协议、CRC、校准 CSV、生产姿态。
