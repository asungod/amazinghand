# 分级训练 AI 建议：电脑本地代理

本功能是可选的报告分析，不参与手势识别、课程完成判定、UART 或机械手控制。MaixCAM2 仍在 8080 端口提供训练网页；模型调用由**打开该网页的同一台电脑**上的代理执行。网页不会自动调用模型，只有点击“生成 AI 下次训练建议”才发送本次课程摘要。设备与浏览器中都不保存 API Key。

## 启动（Windows PowerShell）

1. 在电脑浏览器打开 MaixCAM2 的训练网页。当前设备来源是 `http://10.78.64.1:8080/control`。`--origin` 必须与地址栏中的协议、IP、端口**完全一致**，但不包含 `/control`。
2. 在仓库工作区根目录打开 PowerShell，运行：

   ```powershell
   python -m smart_hand.ai_course_advice_proxy --origin "http://10.78.64.1:8080" --prompt-key
   ```

3. 在终端的 `AI API Key:` 提示下输入密钥，输入内容不会回显。代理默认仅监听电脑的 `127.0.0.1:8765`，不会向局域网开放。
4. 完成至少一项分级训练后，在**同一台电脑的浏览器**点击“生成 AI 下次训练建议”。页面中的“AI 训练分析 · 下次怎么练”卡片会直接展示状态、本次记录数、完成数、待复核项目和模型建议；成功后 AI 文本也会追加到本次报告，下载报告时一并保存。没有真实模型响应时，卡片明确显示待生成或暂不可用，不会把规则建议冒充成 AI 输出。

默认服务商为 DeepSeek，接口基址 `https://api.deepseek.com`。2026-10-01 对照官方 Chat Completions 文档和模型价格页，当前模型 ID 是 `deepseek-flash`（DeepSeek-V4.1-Flash）和 `deepseek-v4-pro`（DeepSeek-V4-Pro-0813）。默认使用已核实的 `deepseek-flash`。`deepseek-chat`、`deepseek-reasoner` 已停用；`deepseek-v4-flash` 只是兼容别名，不作为默认值。发给 DeepSeek 的请求关闭思考模式，以免短建议被默认思考过程占满。也可在启动前通过 `OPEN_SIGN_AI_BASE_URL` 和 `OPEN_SIGN_AI_MODEL` 指定兼容 Chat Completions 的 HTTPS 服务商与模型；换服务商前先确认接口兼容。密钥只从 `DEEPSEEK_API_KEY` 或终端隐藏输入读取，不回显，不进网页、源码、日志或 Git。

## 数据边界与失败处理

- 上传给模型的只有用户点击按钮后确认的匿名课程摘要：课程级别、已结束项目的课程 ID、终态、耗时、结束时置信度、原因枚举，以及模仿阶段网页轮询观察的低置信度/未检测到手/手型不符/视觉过期次数和最长稳定时间。动态课程若有步骤进度，还会发送受限的 `completed_steps/total_steps/complete`。代理再附上固定的评价限制。**不发送图像、原始关键点、姓名或设备控制指令**。
- 新动态课程按二维动作顺序原型评价；没有步骤字段的旧结果仍只代表关键帧，不能写成完整连续动作通过。分析卡片和下载报告都分列“本次不足”“证据局限”“下次练习建议”。模型文字只作参考，不改变课程判定，不触发 UART 或机械动作。
- 轮询次数不是独立视频帧数，也不是识别准确率；AI 建议只能作为参考。网页可选择开启本机匿名记录，最多保存最近 20 次课程；刷新后可恢复已记录结果，但不会恢复或自动启动进行中的训练。未开启保存时，刷新会丢失本页记录。
- 针对性复练的摘要额外包含 `plan`：最多 3 个、无重复、属于原级别的已知课程 ID；记录必须按此计划顺序排列。代理不会接受任意课程、自由文本指令或动作参数。
- 本地代理未启动、来源地址不匹配、密钥缺失、模型超时或返回异常时，页面保留原有规则报告并显示失败提示；不会重试，也不会自动开始任何训练。
- 代理只允许配置的 MaixCAM2 网页来源跨域访问，单次请求正文最多 4096 字节，调用间隔至少 5 秒。浏览器端 15 秒、服务商请求端 12 秒超时。不要把代理改为监听 `0.0.0.0` 后直接暴露到局域网。

## 停止与核验

在代理终端按 `Ctrl+C` 即可停止；网页的训练与规则报告仍可运行。主机测试：

```powershell
python -m unittest smart_hand.tests.test_ai_course_advice_proxy smart_hand.tests.test_web_stream -q
```

这些测试使用伪造服务商响应，不消耗 API 额度，也不代替真实账号调用。2026-10-01 的现场探测：电脑环境变量 `DEEPSEEK_API_KEY` 未设置，因此没有发起成功的建议调用，状态为尚未联通。向 `https://api.deepseek.com/chat/completions` 发送非密钥占位符，服务商返回 HTTP 401，代理记为 `api_key_rejected`。同一地址在 0.001 秒时限下记为 `provider_timeout`；连到本机未监听的 `https://127.0.0.1:9` 记为 `provider_unavailable`。这些失败都没有写成模型建议。代理未对设备上传，网页只同步到本地候选目录。有密钥后，在同一台电脑按上面的命令启动，再在浏览器里点一次按钮，才能把成功调用记为已联通。
