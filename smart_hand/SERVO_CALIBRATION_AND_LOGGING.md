# 单指舵机校准与数据记录规范

## 1. 适用范围

本文用于 AmazingHand 单指的 2 只 SCS0009 的首次识别、低风险校准和数据采集。
2026-08-11 已完成空载总线与小幅运动基线；机械中心、方向、软限位和负载含义仍须在
单指实装后验证。本文中的确认开关只防止误运行，不能代替操作者检查和断电能力。

**当前状态（2026-08-15）**：两颗舵机**已固定进单指 Finger Frame**；舵盘与球头拉杆**均未安装**；
`M2x18` 螺纹杆运输中，机械动作与完整标定**暂停**。装配顺序已按官方
`Assembly.pdf` 裁决，见 `docs/SINGLE_FINGER_ASSEMBLY_ORDER_RECONCILIATION_2026-08-15.md`；
门控见 `docs/SINGLE_FINGER_MOUNTED_CALIBRATION_GATE_2026-08-15.md`。本文不构成执行授权。

配套空白模板：

- `config/servo_calibration_template.csv`：一只舵机一行的版本化校准表；
- `data/grasp_trial_manifest_template.csv`：一次试验一行的固定条件表；
- `data/single_finger_log_template.csv`：单指两舵机逐时刻记录表。

## 2. 当前已确认与未确认内容

已确认：

- 单指使用 2 只 SCS0009；
- 两颗舵机均为型号值 `1284`，总线波特率为 1,000,000；
- 新舵机默认 ID 为 1，当前第一颗保持 ID1，第二颗已改为 ID2，并联读回稳定；
- 微雪 Python SDK 可读取原始位置、电压和温度，并可执行位置、速度与力矩使能命令；
- 空载单颗小步运动、双舵机同步小步运动、回位和释放力矩已通过；
- **两颗舵机已固定进 `Finger Frame Part1/Part2`（2026-08-15）；舵盘与球头拉杆均未安装**；
- 舵机使用独立 6V 限流电源；转接板外部电源只可选择绿色端子或DC圆孔之一；
- 首次机械动作必须低速、小范围、逐只舵机进行；
- PC校准脚本直接控制Waveshare转接板，不经过Titan生产 `ServoCommandGate`；校准阶段必须依靠人工断电、限流、温度阈值和脚本本地检查。

尚未确认：

- Titan 端最终使用的 SCS0009 驱动及其调度/超时行为；
- 两个关节的正方向、中心位置、机械软限位和安全停止方式；
- `load` 是否为带方向的估计负载、如何缩放，以及它与真实力矩的关系；
- 实际可持续达到的两舵机反馈采样率；
- **手指机构本体（Proximal / Distal / Gimbal / Link + 轴 + `M2 L25mm`）是否已装配**——仓库内无记录；
- **柔性指壳（Proximal_Shell / Distal_Shell）是否已打印**——早期交接记为「因无法打印 TPU，默认尚未打印」；
- **十字舵盘是否已按官方 p6 改制为 Custom servo horn**；
- **到货的 `M2x18` 数量是否满足官方每指 2 根，且 `M2 L25mm` 是否在手**；
- **装框所用 M2×6 是否与官方 `2x7` 同为自攻型、少约 1 mm 啮合是否足够夹紧**
  （「顶到底/顶穿/顶壳」已由官方 STL 几何证伪，见 `docs/SINGLE_FINGER_SERVO_PLACEMENT_AUDIT_2026-08-15.md` §4）。

在这些内容通过手册、驱动源码和实物读回共同确认前，所有位置、速度、负载、电压和
温度首先按原始寄存器值保存。不得把原始位置直接标成角度，也不得把负载值标成牛顿、
牛米或精确接触力。

## 3. 文件与版本规则

空白模板不能直接覆盖使用。每次开始采集时复制并重命名，例如：

```text
config/servo_calibration_v001.csv
data/20260820_trial_manifest.csv
data/20260820_trial_T0001.csv
```

- `calibration_version` 在校准表、试验清单和逐样本日志中必须完全一致；
- `firmware_hash`、`policy_version`、`driver_name` 和 `driver_version` 必须记录；
- 改动 ID、方向、软限位、速度上限或寄存器换算后必须生成新校准版本；
- 原始数据只追加或另存，不在采集后手工“修正”数值；错误试验保留并写明原因；
- 每次试验只能对应一个 `trial_id`，训练/验证/测试将来必须按整次试验拆分。

## 4. 到货后的安全操作顺序

> **当前执行状态（2026-08-15）：阶段 B 起全部暂停，`M2x18` 螺纹杆未到货。**
> 本节各阶段是**顺序规范**，不是当前执行授权；阶段 C、D 中出现的
> `center_hold_scs0009_pair.py` 与 `finger_smoke_scs0009.py` 命令**当前均不具备执行条件**，
> 且每次运行都需 Codex 主模型在现场单独授权。

### 阶段 A：不装入手指，逐只识别

1. 舵机转接板不接电，按丝印并用万用表检查电源极性和D/V/G定义，不按导线颜色猜测；
2. 绿色端子与DC圆孔二选一作为唯一外部舵机电源入口；Type-C只连接电脑、负责数据/控制；
3. PC校准期间Titan与MaixCAM2均与舵机转接板断开；
4. 只接 1 只舵机，实验电源设为 6.0V、1.0A限流；
5. 只执行只读扫描/查询，记录型号、固件、当前 ID、波特率和所有可读反馈；
6. 第二只舵机重复相同步骤；
7. 若两只舵机 ID 相同，保持一次只连接一只，分别改成唯一 ID 后断电重读确认；
8. 不连接机械结构时，才允许极低速、小步长验证转向和反馈是否变化。

任一阶段出现反接、异常发热、持续限流、通信大量丢失或不受控运动，应立即关闭舵机
电源；不能靠继续发送命令来假定能够停止。

### 阶段 B：断电机械装配（手指机构与球头拉杆）

> **2026-08-15 顺序修订**：本阶段原为「固定舵机、置中并安装舵盘」。
> 按官方 `Assembly.pdf` p19 → p20 → p22，**球头拉杆必须先接到 link，舵盘随后才在电气中点压上输出轴**，
> 故装舵盘已移到阶段 C。裁决依据见 `docs/SINGLE_FINGER_ASSEMBLY_ORDER_RECONCILIATION_2026-08-15.md`。

**装框已于 2026-08-15 完成**（ID1/ID2 已固定进 `Finger Frame Part1/Part2`，未装舵盘与拉杆），
因此本阶段不再包含"把舵机固定进框架"这一步，也不要求重复装框。
装框的官方核对判据（正视输出轴、指根枢轴在上、线缆向下时 ID2 在左、ID1 在右；
两颗输出轴远离指根大转轴；螺钉从带 ⌀2.2 沉孔的一面拧入）用于**断电照片审查**，
不是重装指令。

本阶段全程**断电**（外部 6V 关闭、确认 `torque=0`），按官方顺序：

1. **手指机构本体**（官方 p13–p16）：Proximal / Distal / Gimbal / Link + D2x10、D2x16 轴，
   `M2 L25mm` 螺纹杆插入 link；按 p16 装指壳，4× 热塑螺钉 2.5x6，不要拧过紧；
2. **球头拉杆 ×2**（官方 p10–p11）：每根 = 2× M2 球头 + **1× `M2 L18mm`** + 1× Spacer，
   用 Length tooling 定长后把一只球头旋转 90°；
3. **舵盘组件 ×2**（官方 p12）：Custom servo horn + `M2x10` 螺钉 + `M2` 螺母，
   把舵盘固定到球头拉杆一端；
4. **手指机构插入指框衬套**（官方 p19）：`M2.5` 大垫圈 + `2.5x8` 热塑螺钉锁进 gimbal 孔，
   不要拧太紧，手动确认外展/内收顺畅且间隙最小；
5. **球头拉杆自由端接到 link 的 M2 螺纹杆**（官方 p20），两侧 `M2` 螺母锁紧
   （接触后再多拧至少半圈）；**此时舵盘仍悬空、未上输出轴**；
6. 在不强拧输出轴的前提下手动检查机构有无装反、干涉或死点。

> **当前阻断**：`M2x18` 螺纹杆运输中。缺该杆则做不出球头拉杆（p11），
> 进而做不出舵盘组件（p12），官方顺序下**舵盘也无法安装**。
> 因此不存在"先装舵盘、只等零件装连杆"的中间选项。

### 阶段 C：电气中点参考、安装舵盘与精调

只有阶段 B 完成并经主模型明确批准后执行：

1. 关闭 6V 输出，将限流从 1.0A 设为 2.0A；复核输出轴周围无零件或人手；
2. 运行
   `host/center_hold_scs0009_pair.py --port COM4 --hold-seconds 120 --frame-mounted-confirmed`；
   程序将两颗舵机依次低速移到原始位置 511（**电气中点参考，不是已测机械中心**）并保持力矩；
3. 保持期间按官方 p22 / p26 的相位把舵盘压上输出轴，用 `M2x4` 中心螺钉固定；
   官方相位判据是图示比对，正文写明只能 `as closed as you can`；
   异常声音、持续 CC 或卡滞时立即切断 6V；
4. 保持结束或按 Ctrl+C 后程序释放力矩；
5. 按官方 p23 / p27 精调中点：**手指闭合时舵盘应与舵机中平面对齐**；
   Arduino 路线 1 step = 0.293°；官方示例把 ID1 从 511 调到 520、ID2 保持 511。

### 阶段 D：实测安全范围与完整单指低幅冒烟

1. 手动确认全行程无明显卡滞，记录两舵机实际动作方向和机构趋势；
2. 逐步确认方向并探测保守软限位，在接近硬限位前人工停止；结果写入
   `soft_min_raw`、`soft_max_raw`，硬限位观察值只写备注；**不得直接采用 20、511、1003**；
3. 取得两颗舵机各自的实测安全参考值后，才可运行
   `host/finger_smoke_scs0009.py --center1 <ID1实测值> --center2 <ID2实测值>` 的 ±12 原始计数小幅测试；
   脚本不再把 511 默认成机械中心，两个 center 参数为必填；
4. 先使用软物体或空载，保持低速和小动作范围；
5. 同时记录两舵机的命令、反馈、读取是否成功和数据年龄；
6. 分别验证空载闭合、轻触、保持、释放和受控阻挡；
7. 每次只改变一个变量，且人工能够立刻切断 6V 舵机电源。

阶段 B、C 未通过时不得进入阶段 D。单指通过也不代表 8 舵机供电与总线已经通过。

**方向不得推断**：官方 `Overview.pdf` p2 只说「同向＝屈伸、反向＝内收外展」，
未给出与 SCS0009 原始寄存器方向的映射，且官方 p23 / p27 自述 `rotation way is not obvious`
→ `direction_sign` 必须实测。

当前电脑上转接板枚举为 `COM4`，但端口号可能因 USB 接口或电脑改变；脚本命令中的
`COM4` 只代表本次实测环境。置中会从当前约 20/1000 的位置产生明显转动，因此只能在
舵机已固定且没有舵盘/连杆施加载荷时执行。运动、保持和校准期间任一舵机温度达到
50°C立即关闭6V输出；45°C可作为预警值。

## 5. 校准表字段

`servo_calibration_template.csv` 的关键字段：

| 字段 | 填写规则 |
|---|---|
| `servo_role` | 先使用稳定的逻辑名称，如 `finger1_joint1`、`finger1_joint2` |
| `servo_id` | 断电重启后再次读取确认的总线 ID |
| `direction_sign` | 原始命令增加时逻辑角度增加填 `1`，相反填 `-1`；未验证留空 |
| `center_raw` | 机械安全中心对应的原始位置 |
| `soft_min_raw` / `soft_max_raw` | 留有机械裕量的软件边界，不是硬碰硬得到的极限 |
| `max_step_raw` | 控制周期内允许的最大命令变化；实测前留空 |
| `speed_limit_raw` | 驱动原始速度配置；单位确认前不写成 rpm 或度每秒 |
| `position_unit_status` | 只能填 `raw_only` 或确认换算后的 `confirmed` |
| `load_unit_status` | 初始固定为 `raw_only`，除非厂商资料和实测均支持换算 |
| `verified_by` / `verified_at` | 实际操作者和校验时间 |

只要 `center_raw`、两个软限位、方向或唯一 ID 中任一项为空，该舵机就不能进入自动抓握。
`host/servo_safety_model.py` 会按此规则加载恰好两行校准，并在电脑端模拟未来 Titan
动作出口的失败关闭行为。上层策略只提供相对中心的逻辑偏移，`direction_sign` 在这一
层转换为原始目标；AI/视觉代码不得自行处理舵机正反方向或绕过软限位。

## 6. 试验与逐样本字段

### 6.1 试验清单

`grasp_trial_manifest_template.csv` 保存整次试验不变化的条件，包括对象类别、质量和
尺寸、电源条件、校准版本、固件哈希、抓握意图、预期状态和最终人工标签。

首轮信号验证可使用：

- `EMPTY_CLOSE`：空载闭合；
- `SOFT_CONTACT`：轻触软物体；
- `HOLD`：在安全范围内短时保持；
- `CONTROLLED_BLOCK`：低速低限流的人工受控阻挡；
- `RELEASE`：释放。

`CONTROLLED_BLOCK` 只用于确认异常反馈是否可辨，不用于制造堵转数据。出现持续限流、
异常温升或机构卡死应立即终止并把 `aborted=1`。

### 6.2 单指逐样本日志

`single_finger_log_template.csv` 为宽表，每行是同一 Titan 单调时钟下的一次采样。两只
舵机分别记录：目标位置、实际位置、速度、负载、电压、温度的原始值，以及读取成功
标志和数据年龄。`sample_seq` 必须单调递增；读取失败时保留该行，`read_ok=0`，对应
原始字段留空，不能用上一帧值冒充新读数。

首轮目标约 20Hz，但这只是采集目标。需要实测 2 只、随后 8 只舵机的总线轮询耗时，
并保证通信、安全状态机和急停处理优先。若采样周期抖动，真实 `time_ms` 比假定的固定
周期更重要。

## 7. 最小验收标准

正常路径：

- 两只舵机 ID 唯一，断电重启后可稳定读回；
- 小步命令的方向和位置反馈一致；
- 单指空载低速闭合/释放不碰机械限位；
- 日志中的时间、序号、试验 ID 和校准版本连续且可追溯。

失败路径：

- 任一读取失败被明确记录，旧值不伪装为新值；
- 超软限位命令在下发前被拒绝；
- 通信超时、持续限流或异常温升会终止试验并撤销授权；
- 断电后重新上电仍保持默认禁止自动动作。

集成边界：

- Maix 的旧 VISION 不能触发新的舵机动作；
- 舵机日志采集不能阻塞 UART2 通信或动作安全线程；
- 两舵机成功不外推为 8 舵机总线、电源或实时性结论。

## 8. 采集后第一轮分析

先画出原始位置、位置误差、速度、负载、电压、温度随时间的曲线，并把人工事件时间
标在同一图中。重点回答：空载、轻触和受控阻挡是否存在可重复差异，读取失败和电源
限流是否会产生伪特征。若信号不可分，优先修正采样、机械装配或传感来源，不训练
Titan 模型；若简单阈值已经可靠，先保留规则基线，再判断第二级 AI 是否真正增加价值。

电脑端分析命令：

```powershell
python host\analyze_servo_log.py data\20260820_trial_T0001.csv `
  --output data\20260820_trial_T0001_report.html
```

脚本只依赖 Python 标准库，会检查必需列、单调时间、严格递增样本序号、单文件唯一
trial，以及读取失败行不能携带“新鲜反馈值”。输出 JSON 摘要和位置/目标、负载、
电压、温度的原始值曲线。它不会自动解释接触、滑移、力矩或物理单位。
