# Titan 动作安全门参考设计

## 状态与边界

本文定义未来 Titan 动作层进入真实舵机控制前的最小授权边界。当前实现仅为
`host/action_safety_model.py` 中可测试的 Python 参考模型，没有接入 Titan RT-Thread
固件，也不会产生舵机命令。

安全门只回答两个问题：是否允许开始新动作，以及运行中的动作是否必须请求安全
停止。它不决定安全停止最终采用保持位置、缓慢回安全位还是 torque-off；该选择依赖
机械卡滞、负载、供电和舵机反馈的真机测试。

## 必须保持的不变量

- 上电默认 `DISARMED`，即使已经收到目标也不能自动动作。
- 只有链路在线、人工/上层明确 arm、无锁存故障且目标新鲜时，才允许开始动作。
- 目标新鲜度使用 Titan 本地接收时刻和单调时钟计算，不信任发送端时间。
- 相同序号、旧序号或乱序 VISION 不刷新目标时间；16 位序号从 65535 回到 0 可接受。
- 链路离线会立即撤销 arm、清除目标；若正在动作则产生 `safe_stop_required`。
- 目标超过配置时限仍未更新时，新动作被禁止；运行中的动作产生
  `safe_stop_required`。
- 故障锁存会撤销 arm、清除目标并请求停止；清除故障后仍必须重新 arm 并收到新目标。
- `safe_stop_required` 只是给未来执行层的请求，参考模型绝不假定舵机已经安全停止。

## 尚未解决的序号会话边界

当前参考模型假设 Maix 重启前 Titan 能观察到链路离线，从而清除旧序号基线。如果
Maix 在 1.5 秒离线门限内快速重启并立即从序号 0 发送，Titan 可能仍把它视为旧序号。
正式接入前应增加 boot/session 标识或显式序号基线重置事件；在协议没有该信息时，
不能简单允许任意不同序号刷新目标，否则乱序旧帧也可能恢复动作授权。

## 参考接口

| 接口 | 用途 | 关键结果 |
|---|---|---|
| `set_link(online)` | 接收 Titan 通信层 ONLINE/OFFLINE 状态 | 离线时撤销授权并可能请求停止 |
| `arm()` / `disarm()` | 显式动作授权 | 不允许上电自动 arm |
| `note_target(seq, now_ms)` | 接收合法的新 VISION | 重复/旧序号不会刷新时间 |
| `start_motion(now_ms, elapsed_ms)` | 动作开始前最后一道门 | 任一条件不满足即返回 `False` |
| `tick(now_ms, elapsed_ms)` | 动作运行期间周期检查 | 目标过期时请求安全停止 |
| `latch_fault()` / `clear_fault()` | 故障锁存与人工恢复 | 清除后仍需重新 arm 和新目标 |

## 接入 Titan 前的顺序

1. 先完成现有 Titan 通信基线的 J-Link 烧录、UART1 日志和 UART2 联调，不能把本
   参考模型提前复制进尚未上板验证的固件。
2. 根据单指空载测试确定目标新鲜度、动作超时和安全停止的实际执行策略。
3. 将参考模型映射为 Titan C 状态机，并让通信线程只投递事件，不直接驱动舵机。
4. 用软件限位、低速小角度和独立 6V 限流电源验证正常完成、目标过期、链路断开和
   故障锁存四条路径。
5. 只有确认执行层完成安全停止后，才能把 `safe_stop_required` 记录为已处理。

## 电脑端验证

```powershell
python -m unittest tests.test_action_safety_model -v
```

测试覆盖默认禁止、正常授权、750ms 边界、断联停止、重复/旧序号、序号回绕和故障
锁存。它只能证明状态逻辑，不能证明真实舵机、供电或机械结构已经安全。
