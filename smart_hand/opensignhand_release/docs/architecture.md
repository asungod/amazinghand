# OpenSignHand 系统架构

## 1. 目标与边界

OpenSignHand 的第一阶段目标是让摄像头端识别少量基础手型，并把训练过程变成可重复、有安全边界、可记录的边缘 AI 交互。它不是把完整手语词汇送进机械手，也不是让语言模型直接控制舵机。

## 2. 数据流

```text
┌──────────────────────┐
│ MaixCAM2             │
│ 摄像头 + 视觉处理    │
│ 手部姿态/手型状态     │
└──────────┬───────────┘
           │ UART2: $TYPE,seq,args*CRC\r\n
           ▼
┌──────────────────────┐
│ Titan Mini            │
│ RT-Thread             │
│ 解析、ACK、时效校验   │
│ 训练/安全状态机       │
└──────────┬───────────┘
           │ 仅输出已授权的结构化动作意图
           ▼
┌──────────────────────┐
│ SCS0009 TTL 总线      │
│ 舵机反馈与故障监测    │
└──────────┬───────────┘
           ▼
┌──────────────────────┐
│ AmazingHand           │
│ 既有安全动作链路      │
│ 辅助示范（真机待验证）│
└──────────────────────┘
```

MaixCAM2 负责高带宽视觉输入，Titan 负责低带宽、可审计的状态和安全判断。结构化消息中不传原始图像，减少链路负担，也让 Titan 可以检查序号、CRC、ACK、超时和视觉新鲜度。

## 3. 当前协议事实

由 `../maixcam2/protocol.py` 可确认：

- 消息类型包括 `PING`、`ACK`、`VISION`、`STATUS`、`TRAIN`、`TRAINSTAT`；
- 帧格式为 `$TYPE,sequence,args...*CRC16\\r\\n`；
- `MAX_FRAME_SIZE=128`，序号为无符号 16 位，参数为无符号 32 位；
- CRC 为 CRC-16-CCITT；
- 当前生产 UART 入口由部署预检固定为 MaixCAM2 `/dev/ttyS2`、115200 baud；
- 解析失败、CRC 错误、旧序号、视觉过期或链路超时不能直接产生机械动作。

## 4. 训练状态

当前 Maix 训练流程可以分为：

1. `TARGET`：选择课程/目标并稳定获取视觉状态；
2. `HAND`/示范与模仿：识别手部姿态、保持和重复次数；
3. 记录训练质量和结束原因；
4. 完成、取消、超时或故障恢复。

`TRAIN` 消息是训练意图，不是“舵机写入成功”的证明。Titan 的确定性安全门必须再次检查链路、视觉新鲜度、目标可用性、校准和故障状态。

## 5. AI 边界

当前可以诚实描述为：

- MaixCAM2：本地视觉 AI/手部姿态训练处理；
- Titan：RT-Thread 实时状态、安全规则、通信和反馈；
- TitanTrust：视觉/UART 时序可信度的辅助模型原型；
- Titan NPU：当前没有部署手语或音频神经网络。

因此，不能使用“Titan 双 AI 已部署”“Titan NPU 已完成手语识别”等表述，除非后续产生板端模型调用、资源、时延和真机日志证据。

## 6. 开源边界

上游 AmazingHand 的软件/机械许可证和本项目原创增量必须在材料中分开。采购板卡不等于自研硬件；上游手结构不等于本项目机械原创。发布代码前需要逐文件做许可证和敏感信息审查。

## 7. 未来音频入口（非当前能力）

Titan Mini 板载 PDM 麦克风可以作为教师/家属的有限关键词辅助入口，但当前工程没有完成 PDM 采集、关键词模型或 NPU 音频部署。因此它不在本版“已实现”范围内。若后续实现，链路应是：

```text
PDM → 短帧 PCM/VAD → MFCC或Log-Mel → 关键词分类
    → AUDIO_INTENT → 人工确认/现有安全门 → 训练状态机
```

`UNKNOWN` 和静音只能上报，不能触发动作；声音不能成为听障人士或手语学习者训练的必要入口。
