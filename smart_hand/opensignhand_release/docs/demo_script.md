# 3–5 分钟真实演示脚本

本脚本用于整理真实证据，不要求也不允许用动画、模拟日志或口头描述替代尚未完成的功能。若现场没有完整硬件，应明确说“本段为离线演练/软件展示”，不要剪成真机动作。

## 0:00–0:25 项目定位

建议表述：

> OpenSignHand 是一个面向少量基础手型训练的边缘 AI 原型。MaixCAM2 处理视觉，Titan Mini 负责通信、状态和安全校验，AmazingHand 用于反馈训练动作。我们先把三种基础手型做成可重复验证的训练，而不是宣称完成完整手语翻译。

画面：项目名称、上游 AmazingHand 归属、MaixCAM2/Titan Mini 为购买开发板的说明。

## 0:25–0:55 系统链路

展示 `docs/architecture.md` 的链路图，依次指出：视觉、结构化 UART、Titan 状态机、舵机总线、手部反馈。

不要说：Titan NPU 已经部署了手语模型、机械手本体是团队原创、ACK 等于动作成功。

## 0:55–1:45 三种基础手型

依次演示 `OPEN_PALM`、`FIST`、`V_SIGN` 中实际已经通过现场验收的课程。每种课程只使用当前版本的界面和人工确认流程，展示：

1. 目标/课程选择；
2. 示范阶段；
3. 模仿、保持和计数；
4. 完成或取消后的记录。

屏幕上的次数、完成率和耗时必须来自本次会话原始 CSV，不得临时编写数字。

## 1:45–2:35 安全路径

在不造成机械风险的前提下展示一个已准备好的失败证据，例如无目标、视觉过期、断开 UART 或校准缺失。说明：

> 这条链路会拒绝动作或进入安全停止；它说明系统优先保证状态可信，而不是看到一帧图像就驱动舵机。

若没有现场可重复的失败测试，展示已有报告并明确报告边界，不现场制造断线或堵转风险。

## 2:35–3:20 日志与可复现

展示会话 CSV、质量 CSV、原因 CSV，以及离线演练输出中的 `hardware_accessed=false`。说明日志用于复盘训练流程，不是临床诊断。

## 3:20–4:10 开源和原创增量

用一页说明：

- AmazingHand 软件 Apache-2.0、机械 CC BY 4.0；
- MaixCAM2/Titan Mini 为购买开发板；
- 本项目自研的是视觉接入、训练状态机、UART/CRC/ACK、安全门控、质量日志和三种课程组织；
- 第三方数据/模型不随包分发，按链接、许可证、清单和校验流程复现。

## 4:10–4:40 限制与下一步

如实说明：目前只有三种基础手型，不是完整手语翻译器；Titan NPU 尚未部署手语或音频网络；还需要继续完善数据、模型许可证、跨环境复现和真机证据。

## 拍摄检查

- 拍摄前记录代码、固件、模型和硬件版本；
- 画面中遮盖手机号、邮箱、IP、设备密钥和本机路径；
- 任何数字都能回溯到原始文件；
- 出现异响、卡滞、异常发热或掉压立即断电；
- 不要把“计划”“离线 PASS”“通信 ACK”剪辑成“完整机械动作已成功”。
