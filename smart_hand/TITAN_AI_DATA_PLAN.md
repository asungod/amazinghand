# Titan 第二级边缘 AI 数据方案

## 1. 为什么 Titan 还需要第二级 AI

MaixCAM2 已经负责高带宽图像检测，Titan 不应再重复运行同一个目标检测模型。Titan
的合理任务是融合视觉语义、抓握意图和 SCS0009 执行反馈，判断抓握过程是否：

- 尚未接触；
- 接触并稳定；
- 疑似不稳定/滑移；
- 过载、卡滞或通信异常。

这种分工可以形成“视觉感知 AI + 执行状态 AI”，同时保留 RT-Thread 确定性安全门。
AI 输出只提供状态建议，软限位、过温、超时和断联等硬安全规则必须始终优先。

## 2. 当前状态

- Titan NPU 尚未运行任何 Smart Hand 模型；
- 舵机反馈尚未接入 Titan；
- 没有真实抓握数据集；
- 当前 `POWER_GRASP/NO_ACTION` 只是规则字符串；
- 因此现在只能定义数据边界，不能训练或宣称模型精度。

## 3. 建议采集的原始字段

每条记录必须包含同一 Titan 单调时钟下的时间戳。初始目标采样率可设为 20Hz，但必须
根据 8 舵机总线轮询耗时和 RT-Thread 负载实测调整，不能以牺牲通信和安全线程实时性
为代价。

### 3.1 试验元数据（每次抓握固定）

| 字段 | 含义 |
|---|---|
| `session_id` / `trial_id` | 保证训练集按整次试验拆分，防止相邻样本泄漏 |
| `object_class` | bottle/cup/remote |
| `object_mass_g` | 物体实际质量 |
| `object_size_mm` | 直径或厚度等关键尺寸 |
| `grip_intent` | 三种抓握意图之一 |
| `firmware_hash` / `policy_version` | 保证数据可追溯 |
| `supply_voltage_v` / `current_limit_a` | 记录电气条件 |

### 3.2 视觉与链路字段（逐样本）

- Titan 本地接收时间；
- VISION 序号、类别、置信度、检测框中心/宽高；
- 目标年龄；
- 链路 ONLINE/OFFLINE；
- ACK RTT、序号跳变和通信错误计数摘要。

### 3.3 每个舵机的反馈（逐样本）

对 8 个舵机分别采集，单指阶段先采集 2 个：

- 目标位置；
- 实际位置；
- 位置误差；
- 速度；
- 负载/电流等设备实际可提供的反馈量；
- 电压；
- 温度；
- 本次读取是否成功和数据年龄。

字段名称和单位必须依据最终使用的 SCS0009 库/寄存器确认。未经手册和实物校验，
不能把“负载反馈”直接解释为精确力矩或接触力。

### 3.4 系统字段

- 当前状态机状态；
- 是否 armed；
- 当前动作阶段和动作开始时间；
- 故障位、超时位、软限位触发；
- 电源是否进入限流（若只能人工观察，则记录为试验级标签）。

## 4. 标签定义

首版建议使用少量、可人工核验的状态，而不是模糊的“抓得好/不好”：

| 标签 | 定义 | 安全意义 |
|---|---|---|
| `OPEN_IDLE` | 未执行抓握或已经释放 | 不允许误报为稳定抓握 |
| `CLOSING_NO_CONTACT` | 正在闭合但尚未形成有效接触 | 继续动作仍受轨迹和超时约束 |
| `CONTACT_STABLE` | 物体保持且位置/负载在可接受范围 | 可进入 HOLDING |
| `UNSTABLE_SUSPECTED` | 位置/负载变化提示疑似松动或滑移 | 只作提示或受限补偿，不能盲目加力 |
| `OVERLOAD_OR_JAM` | 堵转、过载、卡滞或异常高误差 | 规则层立即优先处理，不等待 AI |

SCS0009 没有真实触觉阵列，仅靠舵机反馈可能无法可靠区分滑移。因此输出名称使用
`UNSTABLE_SUSPECTED`，不得宣称精确触觉或必然检测滑落。

## 5. 数据采集顺序

### 阶段 1：先验证传感可分性

1. 单指低速空载闭合；
2. 单指轻触软物体；
3. 单指在安全限流下模拟受阻；
4. 保存位置、速度、负载、电压、温度和读取错误；
5. 画出曲线，确认不同状态确实存在可重复差异。

每种情况先做少量试验验证数据链路，不训练模型。如果反馈噪声大到无法分辨，就先
改采样/滤波/机械结构，不能用更多网络层掩盖无信息输入。

### 阶段 2：整手受控采集

- 每个物体分别采集正常抓握、未接触、偏置放置和安全范围内的异常；
- 每次试验独立编号，完整记录从 OPEN 到 RELEASE/FAULT；
- 故障样本必须在低速、低限流、软物体和人工急停条件下采集；
- 训练/验证/测试按 `trial_id` 或采集日期拆分，不能随机拆散相邻时间点。

### 阶段 3：训练与部署

1. 先做规则/阈值基线并记录混淆矩阵；
2. 再尝试小型 MLP 或 1D 时序网络，窗口暂定 0.5–1 秒，最终由采样率和真机数据决定；
3. PC 上训练，保留完全独立的测试试验；
4. 检查各状态召回率，尤其是 `OVERLOAD_OR_JAM` 的漏检；
5. 转换为 Titan/Ethos-U55 支持的 INT8 模型；
6. 对比 PC 浮点、PC 量化和 Titan 真机输出；
7. 测量推理时延、峰值 RAM、线程栈和对 UART/舵机轮询的影响。

若小模型没有明显优于规则基线，比赛 MVP 应保留规则状态机，不为了“双 AI”强行使用
低可信模型。

## 6. 运行时安全边界

- NPU 推理运行在低于通信/动作安全线程的优先级；
- 推理超时、模型异常或输入过期时回退到规则层并禁止新的危险动作；
- AI 不得覆盖软限位、温度、电压、堵转和通信超时；
- AI 输出必须带本地时间戳和有效期，旧输出不可复用；
- 模型升级必须记录哈希，并保留上一个可用模型/规则基线；
- 首次加入 NPU 后重新执行 ELF/MAP 资源审计和 `free`/`ps` 真机检查。

## 7. 对评委的准确表述

完成模型部署和真机验证后可以说：

> MaixCAM2 在视觉侧完成物体感知，Titan 使用执行器反馈进行时序状态识别，同时由
> RT-Thread 安全状态机保证通信断联、过载和目标过期时的确定性降级。

模型尚未部署前只能说：

> 当前完成了双边缘架构、通信与数据闭环设计，Titan 的执行状态模型仍在采集真机数据。
